# Feature Landscape

**Domain:** 농업 비료 영업 관리 — 1~2인 소규모 내부용 웹앱
**Researched:** 2026-03-24
**Scope:** Milestone 2 — 고객 DB, 처방 템플릿, 할인율 관리, 매출/미수금 집계

---

## Context: 기존 구현 현황

이미 구현된 기능들은 이번 마일스톤에서 다시 구현하지 않는다. 아래 목록은 추가/확장만 필요한 항목을 명확히 하기 위한 기준선이다.

| 이미 구현됨 | 상태 |
|------------|------|
| 고객 정보 폼 (이름, 연락처, 주소, 지역, 작물, 평수) | index.html cust-bar |
| 전역 할인율 입력 (#gDisc) | 현재 세션 단위, 저장 없음 |
| 미수금 조회 버튼 3종 (전체/현재고객/미입금확인) | UI 존재, 서버 의존 |
| 미입금 내역 모달 (#unpaidOverlay) | UI 존재 |
| 전체 미수금 오버레이 (.au-overlay) | CSS 완성, 로직 연결 필요 |
| 서버 저장 버튼 (doEmail/서버저장) | EmailJS 기반 구현 |
| PDF 처방전 업로드 → 장바구니 자동 적용 | 완성 |

## Table Stakes

이 기능들이 빠지면 마일스톤 목표("고객 대응 시간 단축")를 달성할 수 없다.

| Feature | Why Expected | Complexity | Notes |
|---------|--------------|------------|-------|
| 고객 자동완성 / 불러오기 | 매번 고객 정보를 다시 입력하는 것이 현재 가장 큰 마찰 | Medium | cName blur 시 localStorage 검색 → 드롭다운 |
| 고객별 할인율 저장 및 자동 적용 | 단골 고객마다 다른 할인율이 있고 이를 매번 기억해서 입력 중 | Low-Medium | 고객 선택 시 #gDisc 자동 세팅 |
| 처방이력 저장 (거래명세표) | 발행 후 분쟁/재발행 시 이전 명세 없으면 대응 불가 | Medium | 저장 = 현재 cart 스냅샷 + 고객정보 + 날짜 |
| 기존 처방 불러와 수정·재발행 | 동일 고객의 반복 구매 대응, 처음부터 다시 입력하지 않기 위함 | Medium | 처방이력 목록 → 선택 → cart 복원 |
| 처방 템플릿 (작물 기반) | 신규 고객에게 유사 처방 시작점 제공 | Medium | 기존 처방 중 "이 작물 표준" 지정 기능 |
| 미수금 금액 입력 및 결제 처리 | 현재 미수금 조회는 있지만 금액 기록/해소 로직이 없음 | Medium | 명세표당 "납부" 버튼 + 금액 입력 |
| 기간별 매출 합계 | 월/분기 실적 확인 없이 영업 판단 불가 | Low-Medium | 명세표 목록 집계, 단순 합산으로 충분 |

## Differentiators

있으면 좋지만 없어도 핵심 가치는 유지된다.

| Feature | Value Proposition | Complexity | Notes |
|---------|-------------------|------------|-------|
| 작물 × 평수 범위 기반 템플릿 추천 | "400평 천혜향이면 이 처방 어때요" 자동 제안 | Medium | 템플릿에 cropName + areaRange 저장 |
| 고객 메모 필드 | "이 고객은 현금결제만" 같은 비정형 정보 보존 | Low | 간단한 textarea, 고객 카드에 표시 |
| 지역별 미수금 그룹핑 | 현재 .au-region-card 구조가 이미 준비됨 | Low | cRegion 기반 그룹, CSS 이미 완성 |
| 처방 비교 (이번 vs 지난번) | 어떤 제품이 추가/제거됐는지 빠르게 파악 | High | v1에서 제외 권장 |
| SMS/카카오 알림 발송 | 미수금 독촉, 배송 안내 자동화 | High | 외부 서비스 연동 필요, v1 제외 |

## Anti-Features

이 기능들은 "작아 보이지만 실제로는 복잡도를 크게 높이는" 유혹이다.

| Anti-Feature | Why Avoid | What to Do Instead |
|--------------|-----------|-------------------|
| 로그인/권한 시스템 | 내부 1~2인 사용, 인증 오버엔지니어링 | 단일 localStorage 공유, 서버 없음 |
| 재고 관리 | 별도 시스템 존재, 중복 관리 부담 | Out of scope 유지 |
| 처방전 PDF 생성 (자동 레이아웃) | 기존 PDF 양식 재현이 극도로 복잡 | 현재 인쇄 기능 유지 |
| 다중 사용자 동기화 / 실시간 협업 | 서버 없이 localStorage 기반으로 시작 | localStorage로 충분, 나중에 JSON export/import |
| 제품 가격 히스토리 / 가격 관리 | productDB.js에 가격이 하드코딩됨, 별도 관리 UI는 scope 외 | 가격 변경 시 productDB.js 직접 수정 유지 |
| 고객 포털 / 고객이 직접 조회 | 내부용 앱, 인증 없음 | Out of scope |

## Feature Dependencies

```
고객 DB (localStorage 저장/조회)
  └── 고객 자동완성 (의존: 고객 레코드 존재)
  └── 할인율 자동 적용 (의존: 고객 레코드에 discount 필드)
  └── 처방이력 저장 (의존: 고객 ID 연결)
       └── 기존 처방 불러오기 (의존: 처방이력 레코드)
       └── 처방 템플릿 지정 (의존: 처방이력 레코드 + isTemplate 플래그)
            └── 템플릿 추천 (의존: 템플릿 + cropName/areaRange)
  └── 미수금 기록 (의존: 처방이력 레코드에 paid 금액 필드)
       └── 매출/미수금 집계 (의존: 처방이력 전체)
```

## Feature Specifications (Active Requirements 상세)

### 1. 고객 DB (localStorage)

**v1 must-have:**
- 고객 레코드 스키마: `{ id, name, phone, phone2, address, region, cropName, area, areaType, discount, memo, createdAt, updatedAt }`
- 고객명 또는 연락처 입력 시 자동완성 드롭다운 (기존 고객 검색)
- 고객 선택 시 전체 폼 자동 채우기 (이름, 연락처, 주소, 지역, 작물, 평수, 할인율)
- 신규 고객은 처방 저장 시 자동 등록 (별도 고객 등록 화면 없이)
- 고객 정보 수정은 폼에서 직접 수정 후 저장 시 덮어쓰기

**v1에서 제외:**
- 고객 전용 관리 화면 (목록/편집/삭제 CRUD 페이지) — 필요시 미래에 추가
- 고객 간 중복 감지 알림 — 연락처 기준 단순 매칭으로 충분

**UX 패턴:**
- 고객명 input onInput: localStorage 검색 → 3자 이상일 때 드롭다운 표시
- 드롭다운 항목: `[이름] [연락처] — [작물] [평수]평` 형식
- 선택 시 모든 cust-bar 필드 자동 채우기 + #gDisc 자동 적용
- 기존 고객 선택 후 폼 수정 → "저장" 또는 발행 시 고객 레코드 갱신

---

### 2. 처방이력 저장 / 기존 처방 불러오기

**v1 must-have:**
- 거래명세표 발행(인쇄/서버저장) 시 처방 자동 저장
- 저장 스키마: `{ id, customerId, customerName, cropName, area, date, items: [...cart], totalSupply, status: 'unpaid'|'partial'|'paid', payments: [] }`
- 고객별 처방이력 목록 (고객 선택 상태에서 "이력 불러오기" 버튼)
- 이력 목록 UI: 날짜 / 작물 / 금액 / 상태(미납/완납) 카드 리스트
- 처방 선택 시 cart 복원 + 고객 정보 채우기 (날짜는 오늘로 리셋)
- 복원 후 수량/제품 수정 가능

**v1에서 제외:**
- 처방 삭제 (실수 방지를 위해 숨김 처리만, 실제 삭제 없음)
- 처방 간 diff 비교

**UX 패턴 (복사/수정 워크플로):**
```
[고객 선택] → [처방이력 버튼 클릭] → 이력 목록 모달 열림
→ 카드 선택 "이 처방으로 시작" → cart 복원됨
→ 날짜 = 오늘, 제품/수량 수정 가능
→ 인쇄/저장 → 새 처방이력으로 저장됨 (원본 유지)
```

핵심 UX 원칙: **복사 후 편집**이지 원본 수정이 아님. 이전 처방이 보존되어야 분쟁 해소 가능.

---

### 3. 처방 템플릿

**v1 must-have:**
- 기존 처방이력 중 하나를 "템플릿으로 지정" 가능 (`isTemplate: true` 플래그)
- 템플릿 목록: 작물별 그룹핑 (예: "천혜향 표준", "수박 기본형")
- 신규 고객 입력 시 "작물 일치 템플릿" 추천 배너 (1줄)
- 템플릿 선택 → cart 채우기 (고객 정보 유지, cart만 대체)

**v1에서 제외:**
- 작물 + 평수 범위 자동 매칭 — 수동 지정으로 충분
- 템플릿 편집 전용 화면 — 처방이력 → 지정 방식으로 충분

**UX 패턴:**
```
처방이력 카드에 "템플릿으로 설정" 토글 버튼
→ 설정 시 해당 처방이 "작물 템플릿 목록"에 등장
→ 신규 고객 작물 선택 시: "천혜향 템플릿 있음 — 불러올까요?" 배너
→ 배너 클릭 → cart 복원
```

---

### 4. 고객별 할인율 관리

**v1 must-have:**
- 고객 레코드에 `discount` 필드 (0~100 정수)
- 고객 선택 시 #gDisc 자동 세팅
- #gDisc 수정 시 현재 세션에만 적용 (고객 레코드 자동 갱신 없음 — 실수 방지)
- 고객 레코드 저장 시 "현재 할인율을 이 고객 기본값으로 저장" 확인 옵션

**v1에서 제외:**
- 제품별 개별 할인율 저장 (제품 모달에서 이미 개별 할인율 입력 가능)
- 할인율 히스토리 / 변경 이력

**UX 패턴:**
- 고객 불러오기 시: `"홍길동 고객 — 기본 할인율 15% 자동 적용됨"` 토스트 알림
- #gDisc 옆 작은 아이콘: "이 값을 고객 기본값으로 저장" 버튼 (저장 전까지 임시)
- 할인율 0인 고객도 명시적으로 "0% 저장" 가능 (null vs 0 구분)

---

### 5. 거래이력 및 매출 관리

**v1 must-have:**
- 처방이력에 결제 기록 추가: `payments: [{ date, amount, note }]`
- 명세표 카드에 "납부 입력" 버튼 → 금액 + 날짜 입력 모달
- 납부 후 잔액 자동 계산 (`totalSupply - sum(payments)`)
- 상태 자동 갱신: `unpaid` / `partial` / `paid`
- 미수금 전체 목록 (.au-overlay): 미납/부분납 처방만 필터, 지역별 그룹핑 (기존 CSS 활용)
- 기간 필터 (이번 달 / 지난 달 / 직접 입력) + 매출 합계 표시
- 인쇄 지원: 미수금 전체 목록 인쇄 (기존 `body.print-au` 스타일 활용)

**v1에서 제외:**
- 세금계산서 자동 발행 / 회계 시스템 연동
- 수금 담당자별 집계
- 엑셀 내보내기 (추후 JSON export로 대체 가능)
- 월별 차트 / 그래프 — 숫자 합산으로 충분

**매출 집계 화면 최소 구성:**
```
┌─────────────────────────────────┐
│ 매출 현황    [이번달▼] [인쇄]   │
├──────────────┬──────────────────┤
│ 발행 금액    │     X,XXX,XXX원  │
│ 수금 완료    │     X,XXX,XXX원  │
│ 미수금 잔액  │       XXX,XXX원  │ ← 강조
├──────────────┴──────────────────┤
│ 명세표 목록 (날짜/고객/금액/상태) │
│ [홍길동] [천혜향] [230,000] [미납]│
│ [김철수] [수박]   [180,000] [완납]│
└─────────────────────────────────┘
```

## MVP Recommendation

### Phase 순서 (의존성 기반)

1. **고객 DB + 자동완성** — 모든 이후 기능의 기반 (customerId 없으면 처방이력 연결 불가)
2. **처방이력 저장** — 미수금 관리의 기반 데이터
3. **기존 처방 불러오기 + 템플릿** — 처방이력 있어야 구현 가능
4. **할인율 자동 적용** — 고객 DB 완성 후 필드 추가만으로 구현
5. **미수금/납부 처리** — 처방이력 스키마에 payments 추가
6. **매출 집계 화면** — 처방이력 + payments 데이터 완성 후 집계 뷰만 추가

### Defer (v2)

- 처방 비교 diff
- 작물 × 평수 범위 자동 매칭
- 엑셀 내보내기
- 고객 전용 CRUD 관리 화면

---

## Technical Constraints (Feature에 영향)

- **localStorage 한계**: 5~10MB. 처방이력에 항목 이미지나 PDF 바이너리는 저장 불가. 텍스트/JSON만.
- **단일 기기 사용**: localStorage는 기기별 분리됨. 2인이 다른 기기 사용 시 데이터 미공유 → JSON export/import로 백업 지원 필요
- **바닐라 JS**: 컴포넌트 라이브러리 없음 → 자동완성 드롭다운 직접 구현 (비교적 단순)
- **서버 없음**: 미수금 조회 버튼들이 현재 "서버에서 조회" 로직 포함 → localStorage 기반으로 전환 or 병행
