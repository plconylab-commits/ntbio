## Visuals

Primary focal point: the `#gName` autocomplete input — it is the entry point for all customer-load interactions. All visual hierarchy decisions should reinforce this as the first interaction target when the customer bar is in view.

## Component Inventory

New components required for this phase. All are plain HTML + CSS injected via `customerUI.js` following the existing `injectValidationCSS()` pattern.

### 1. 고객 이름 자동완성 드롭다운

- **Trigger:** keyup on `#gName` input — fires after 1 character (Korean: single character can be meaningful)
- **Dropdown appearance:** `position: absolute` below `#gName`, `width: 100%` of parent `.fg`, `z-index: 500`, `background: #fff`, `border: 1.5px solid var(--border)`, `border-radius: 0 0 7px 7px`, `box-shadow: 0 4px 12px rgba(0,0,0,.12)`, `max-height: 200px`, `overflow-y: auto`
- **Item height:** 36px, `padding: 8px 11px`, `font-size: 14px`, `font-weight: 500`
- **Item hover:** `background: var(--g-pale)` (`#E0F5F5`)
- **Item selected/active:** `background: var(--g-btn)`, `color: #fff`
- **Keyboard:** ArrowDown / ArrowUp navigates items; Enter selects; Escape closes
- **Match display:** matching substring in customer name shown in `font-weight: 700`; rest stays `font-weight: 500`
- **No results:** show single disabled item "저장된 고객 없음" in `color: var(--muted)`, `font-style: italic`
- **Dismiss:** click outside closes dropdown; focus loss closes after 150ms delay (allow item click)
- **History count badge:** each dropdown item shows 처방이력 count on right side — `font-size: 10px`, `color: var(--muted)`, format: `N건`

### 2. 고객 자동 채우기 (폼 채우기 효과)

- On customer selection: fill `#gName`, `#gCrop`, `#gArea`, `#gPhone`, `#gDisc` instantly
- Visual feedback: each filled field briefly flashes `background: var(--g-pale)` for 400ms via CSS transition then returns to normal — signals auto-fill to user
- `#gDisc` field: if loaded from saved customer, display `background: var(--yellow)`, `border-color: var(--yellow-d)` (existing `.fg.disc` style) — this is the normal state for a saved discount rate

### 3. 할인율 저장 상태 표시

Two visual states for `#gDisc`:

| State | Background | Border | Label |
|-------|-----------|--------|-------|
| Saved (customer default) | `var(--yellow)` `#FFF9C4` | `var(--yellow-d)` `#F9A825` | — |
| Temporary (unsaved change) | `#FFEBEE` (red-lt) | `#EF9A9A` | "임시 변경 — 저장 안됨" badge |

Temporary state badge: `position: absolute`, top-right of discount field, `font-size: 10px`, `font-weight: 700`, `color: var(--red)`, `background: var(--red-lt)`, `padding: 1px 4px`, `border-radius: 3px`.

"이 할인율을 고객 기본값으로 저장" link: appears below `#gDisc` when in temporary state — `font-size: 14px`, `color: var(--g-btn)`, `text-decoration: underline`, `cursor: pointer`.

### 4. 처방이력 건수 배지

- Location: inline after customer name in autocomplete dropdown (see §1 above)
- Also: shown inside `#gName` field as a pill when a customer is selected — `font-size: 10px`, `background: var(--g-pale)`, `color: var(--g-mid)`, `border-radius: 9px`, `padding: 1px 6px`
- Not shown if count is 0

### 5. 고객 저장 / 수정 / 삭제 버튼

Placed in a new `.cust-row3`-style row below existing customer fields (existing `.cust-row3` is already used for date/pyeong/region — add a new `.cust-actions` row below it):

| Button | Label | Style |
|--------|-------|-------|
| Save / Update | 고객 저장 (신규) / 고객 정보 수정 (기존) | `.btn-rx` style: `background: var(--g-btn)`, `color: #fff`, `border-radius: 7px`, `padding: 10px`, `font-size: 14px`, `font-weight: 700` |
| Delete | 고객 삭제 | `.au-del-btn` style: `background: #fff0f0`, `color: var(--red)`, `border: 1.5px solid #FFCDD2`, `border-radius: 5px`, `padding: 8px 12px`, `font-size: 14px` |

Button row layout: `display: flex`, `gap: 8px`. Save/Update button takes `flex: 1`. Delete button is fixed width (`min-width: 72px`).

Delete button is hidden (`display: none`) when no customer is loaded (new entry mode).

### 6. 삭제 확인 (Destructive Confirmation)

- Method: inline confirmation — clicking Delete replaces the button text with "정말 삭제?" and shows two adjacent buttons: "예, 삭제" (`background: var(--red)`, `color: #fff`) and "취소" (`.btn-clear` style)
- No browser `confirm()` dialog — inline only, consistent with existing modal patterns
- Auto-cancel after 5 seconds (restore original state)

## Layout Integration

Phase 2 adds UI to the **existing `.cust-bar`** section only. No new panels or routes.

```
.cust-bar
  .sec-title                        ← existing
  .cust-row1  [고객명 + 작물]         ← existing — wrap gName .fg in position:relative for dropdown
  .cust-row2  [면적 + 연락처]         ← existing
  .cust-row3  [날짜 + 평수 + ...]     ← existing
  .cust-actions  [저장 + 삭제]        ← NEW — added below cust-row3
  #custAutocomplete                  ← NEW — absolute positioned, child of .fg wrapping gName
```

The autocomplete dropdown (`#custAutocomplete`) must be a child of the `.fg` wrapper around `#gName` so it inherits the correct `width: 100%` and `position: relative` context.

## Implementation Notes for Executor

1. **CSS injection pattern:** Follow the exact pattern of `injectValidationCSS()` in `uiController.js` — create a `injectCustomerCSS()` function in `customerUI.js` that inserts a `<style id="cust-css">` tag. Guard with `if (document.getElementById('cust-css')) return;`

2. **CSS token usage:** Use `var(--g-btn)`, `var(--border)`, `var(--g-pale)`, etc. — never hardcode hex values that duplicate existing tokens.

3. **Position context:** Add `position: relative` to the `.fg` wrapper of `#gName` to anchor the absolute dropdown.

4. **Autocomplete z-index:** Use `z-index: 500` — below the modal overlay (`z-index: 1000`) but above normal content.

5. **Discount state management:** Store `customerDefaultDiscount` in a closure variable in `customerUI.js`. Compare current `#gDisc.value` against this baseline on every `input` event to toggle temporary state styling.

6. **No modal for this phase:** Customer save/delete is inline in the existing `.cust-bar`. Do not add a new overlay/modal — keeps the workflow friction-free.

7. **Spacing constraint:** The values 11px and 18px appear only in existing selectors (`.fg input` padding and `.modal-hdr` padding respectively). Do not reuse these values for new elements — use the declared spacing scale tokens (xs/sm/md etc.) instead.
